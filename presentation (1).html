Vision Model 2: BiomedCLIP

📋 Model Specifications

  • 🔹 Type: Vision-Language Model
  • 🔹 Architecture: CLIP (Contrastive Learning)
  • 🔹 Backbone: ViT-Base + PubMedBERT
  • 🔹 Training: PubMed medical literature
  • 🔹 Capability: Zero-shot classification

🎯 Classification Classes

  • 🔴 OCA: Oral Squamous Cell Carcinoma
  • 🟡 OPMD: Oral Potentially Malignant Disorder (leukoplakia)
  • 🔵 Benign: Benign oral lesions (aphthous ulcer)
  • 🟢 Normal: Healthy oral mucosa

⚙️ Zero-Shot Classification Process

Input: Cropped lesion patches from YOLO detections
Text Prompts: Medical descriptions (e.g., "clinical photograph of oral squamous cell carcinoma")
Encoding: Image → Visual features, Text → Semantic features
Similarity: Cosine similarity between image and text embeddings
Output: Class probabilities via softmax (OCA, OPMD, Benign, Normal)

Score Fusion & Clinical Decision Tree

🔀 Fusion Module

Formula: final_score = yolo_confidence × biomedclip_max_score

Purpose: Combines spatial detection confidence with semantic classification confidence
Example: YOLO detects lesion with 0.85 confidence + BiomedCLIP classifies as OCA with 0.92 score = 0.782 fusion score

🌳 Clinical Decision Tree

Step 1: Start with vision score × 10
Step 2: Add risk factors:
• Age > 40 years → +1.5 points
• Tobacco use > 10 years → +2.0 points
• Lesion duration > 6 weeks → +1.5 points
Step 3: Risk Stratification:
🔴 HIGH (score > 8.0): Urgent referral within 2 weeks
🟡 MEDIUM (score 5.0-8.0): Non-urgent referral within 4 weeks
🟢 LOW (score < 5.0): Routine monitoring recommended

The Logit Scale: Critical Component

🔬 What is Logit Scale?

A learned temperature parameter in CLIP models that scales the similarity scores between image and text embeddings

❓ Why Extract It?

  • 🔸 Confidence Calibration: Ensures probability scores remain accurate after INT8 quantization
  • 🔸 Model Consistency: Must match the checkpoint used for ONNX export
  • 🔸 Inference Requirement: Applied during similarity scoring: similarity × logit_scale
  • 🔸 Tiny File: Only 201 bytes but critical for accuracy!

📐 How We Calculated It

1. Load Model:
model = open_clip.create_model(...)
model.load_checkpoint(...) 2. Extract Parameter:
logit_scale = model.logit_scale.exp().item() Why .exp()? Stored as log(scale) internally
3. Save with Metadata:
json.dump({'logit_scale': 85.23, ...})

✅ Usage in Inference

Step 1: image_features = vision_encoder(image) # TensorRT INT8
Step 2: image_features = normalize(image_features) # L2 norm
Step 3: similarity = image_features @ text_features.T # Cosine similarity
Step 4: scaled = similarity × logit_scale # 🔥 Apply learned temperature!
Step 5: probs = softmax(scaled) # Final class probabilities

Our Value: 85.23 (expected ~100 for CLIP models ✓)

TensorRT INT8 Quantization Results

Why Quantization?

Jetson Nano has limited resources - we need to optimize BiomedCLIP (ViT-B/16) to run efficiently on edge devices with only 4GB RAM and constrained GPU memory

  • 🧠 Memory Usage: Higher GPU memory
  • ⏱️ Inference: ~461 ms (GPU) or ~4782 ms (CPU)
  • 🔢 Precision: 32-bit floating point

✅ After: TensorRT INT8

  • 💾 Engine Size: ~169 MB (INT8 optimized)
  • 🧠 Memory Usage: Reduced GPU footprint
  • ⏱️ Inference: ~395 ms mean (12x faster vs CPU)
  • 🔢 Precision: 8-bit integer quantization

⚡ Optimization Strategy

Vision Encoder: ViT-B/16 ONNX → TensorRT INT8 (169 MB engine)
Text Encoder: Precomputed embeddings (4×512 = 8.2 KB) - eliminates 440MB deployment!
Logit Scale: Extracted temperature parameter (85.23) for similarity scaling

INT8 Calibration: How Quantization Works

🎯 Goal: Find optimal INT8 quantization scales

TensorRT analyzes activation ranges during calibration to minimize accuracy loss when converting FP32→INT8

📊 Calibration Requirements

  • ✓ 250-400 images (oral cavity photos)
  • ✓ Representative dataset (diverse lesions)
  • ✓ Same preprocessing as inference
  • ✓ Run on Jetson Nano (target hardware)
  • ✓ Entropy calibration v2 (recommended for vision)

⚙️ Calibration Process

1. Feed calibration images through ONNX model
2. Collect activation statistics for each layer
3. Compute optimal scaling factors (FP32→INT8)
4. Minimize KL divergence for accuracy
5. Save calibration cache (reusable)

🔬 What Happens Mathematically

For each layer:
FP32_tensor (range: -327.4 to +891.2) → find optimal scale
scale = max(|min|, |max|) / 127 # INT8 has range -128 to +127
INT8_tensor = round(FP32_tensor / scale) # Quantize!

During inference:
INT8_output → FP32_output = INT8_output × scale # Dequantize for next layer

Quantization Challenges & Solutions

🚨 Critical Problem: CUDA Context Conflicts

Issue: PyCUDA (used by TensorRT) and PyTorch both create separate CUDA contexts
Impact: When both libraries try to use GPU simultaneously, context switches cause "invalid resource handle" errors
Root Cause: Device memory pointers allocated in one context become invalid when accessed from another

❌ Failed Attempts

  • 🔸 Manual CUDA context management
  • 🔸 Removing pycuda.autoinit
  • 🔸 Changing load order (TensorRT first)
  • 🔸 Using retain_primary_context()
  • Result: All failed with OOM or context errors

✅ Working Solution

  • 🔹 Separate Processes: Run each model in isolated process
  • 🔹 Sequential Execution: TensorRT first → cleanup → PyTorch
  • 🔹 Alternative: Run PyTorch on CPU for benchmarking
  • Result: No context conflicts, stable inference

💡 Additional Challenges

GPU Memory Limitations: PyTorch pre-allocates significant memory, TensorRT needs ~171MB contiguous space
Error Message: [TRT] [E] IExecutionContext::enqueueV3: Error Code 1: Cuda Runtime (invalid resource handle)
Solution: Aggressive CUDA cleanup with torch.cuda.empty_cache() between models
